# DSH 备份恢复说明

这个文件夹由 DSH 插件「备份与还原点」自动生成并维护，请整体保留，不要只拷走其中的文件。

```
dsh-backups\
├─ 恢复DSH.cmd        ← DSH 打不开时：双击它
├─ restore.ps1        ← 恢复脚本（由 恢复DSH.cmd 调用）
├─ 使用说明.md        ← 本文件
└─ points\            ← 每个还原点一个文件夹
   ├─ 20261123-221843\
   │  ├─ manifest.json   ← 还原点清单（时间、大小、各部分）
   │  ├─ profile\        ← DSH 配置（不含 node_modules）
   │  ├─ sessions\       ← 会话记录
   │  ├─ storages\       ← 本机存储
   │  ├─ attachments\    ← 附件
   │  └─ credentials     ← 登录凭据（明文）
   └─ ...
```

## 一、DSH 能正常打开时：应用内恢复

1. 打开 DSH，进入 **插件（Plugins）** 页面。
2. 找到「备份与还原点」，点开它的详情页。
3. 点「立即备份」创建还原点；在还原点列表里点「恢复」，再点「确认恢复」。
4. 恢复完成后**完全退出 DSH 再重新打开**，配置和会话才会按还原点生效。

恢复前，插件会自动先生成一个「自动快照：恢复…前」的还原点，恢复错了可以再用它恢复回来。

注意：应用内恢复时，DSH 仍打开着的会话会保持不变（运行中的进程会继续往这些日志追加事件，
直接替换会造成断层）。重启 DSH 后这些会话不再被占用，再执行一次恢复即可包含它们；
或者直接使用下面的离线恢复程序，在 DSH 关闭时一次性完整覆盖。

## 二、DSH 崩溃、无法打开时：离线恢复程序

1. **先完全退出 DSH**：任务栏图标右键 → 退出；若界面已无响应，用任务管理器结束 `DeepSeek Harness`。
2. 在文件资源管理器中打开本文件夹，**双击 `恢复DSH.cmd`**。
3. 窗口中会列出所有还原点，输入序号（1、2…）后回车；
   也可以把某个还原点文件夹或 `.zip` 直接拖到 `恢复DSH.cmd` 上。
4. 输入 `y` 确认：程序先把将被覆盖的文件复制到 `%USERPROFILE%\.dsh\.dsh-backup\replaced-<时间>\` 作为回滚副本，再合并覆盖。恢复只覆盖还原点里存在的文件，**`node_modules` 与还原点里没有的文件会原样保留**。
5. 看到「全部部分已恢复」后，重新打开 DSH。

如果程序提示 DSH 仍在运行，说明还没退干净，请先去退出；确认已退出仍被误判时，可在命令行加 `-Force`。

## 三、注意事项

- 登录凭据默认不备份；创建还原点时勾选「同时备份登录凭据」才会生成 `credentials`（明文）。
- 无论是否含凭据，`dsh-backups` 都有会话、附件等私有数据，**整个文件夹请勿上传网盘或分享**。
  插件会自动写入 `dsh-backups/.gitignore`，让整个目录默认不进版本库。
- 还原点包含配置、会话、本机存储、附件；**不包含** `node_modules`（插件包可重新安装）、日志和 `dsh-runtimes` 运行时。
- 离线恢复采用**合并覆盖**：只覆盖还原点里存在的文件，不会删除 `node_modules` 或还原点里没有的文件，所以已安装的插件不会因此消失。
- 版本提示：V1.0.0 的离线恢复会整目录替换 profile，导致 `node_modules` 与已安装插件丢失；
  V1.0.1 起改为合并覆盖。升级后请在插件页打开一次，让本文件夹里的 `restore.ps1` 刷新为新版本。
- 应用内恢复同样只覆盖、不删除；DSH 正在运行时个别文件可能被占用，插件会列出失败的部分，请改用离线恢复程序。
- 删除还原点会直接删除对应文件夹，无法撤销；需要长期保留时，可把整个 `points\<编号>` 文件夹复制到别处保存。
- 恢复程序只依赖 Windows 自带的 PowerShell，不需要安装 DSH 或 Node.js。
- 日志：应用内操作写入 `dsh-backups/logs/plugin.log`；离线恢复写入同目录的 `restore-offline.log`。
  分享日志前请检查是否包含用户名或本机路径。
