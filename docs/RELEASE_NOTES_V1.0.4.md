# DSH 备份与恢复 v1.0.4

适用 DSH 版本：0.2.2-rc.5（开发/测试所用版本）
最低兼容版本：>= 0.2.2-rc.5（由插件 engines.dsh 强制校验）

## 系统支持

- **当前版本仅在 Windows 11 上提供支持与验证。**
- Windows 10、macOS、Linux、Windows Server、Windows on ARM 及其他环境**未支持、未验证**，
  请不要将其视为可用环境。
- DSH 桌面端要求 `>= 0.2.2-rc.5`；本版本开发和测试使用 `0.2.2-rc.5`。
- Node.js 要求 `>= 20`（由 DSH 自带运行时提供）。
- 离线恢复使用 Windows 11 自带的 Windows PowerShell 5.1，不需要额外安装。

## 主要变化

- 备份目录改为每次重新检索 DSH 已注册工作区和当前工作区服务，移除 `location.json` 固定路径依赖。
- 仅当恰好存在一个可访问的 `dsh-backups` 时自动使用；没有时在可访问的合适工作区创建。
- 存在两个或更多 `dsh-backups` 时停止自动选择，显示全部候选路径，并阻断备份、恢复、删除。
- 任一已注册工作区无法检查时同样阻断；不创建新目录，避免数据分叉。
- 用户手动清理多余目录后，可以在插件页点「重新检索」恢复。
- 插件页显示候选路径、无法检查的工作区和安全提示。
- 不修改备份格式与恢复复制逻辑；离线程序的 `$ScriptVersion` 同步为 1.0.4。

## 备份位置与工作区风险

- 备份目录位于 DSH 工作区内；删除、移动、格式化或损坏该工作区，可能导致其中的备份及还原点丢失。
- 删除工作区前，请先把 `dsh-backups` 迁移到其他工作区。
- 正常情况下只应存在一个有效的 `dsh-backups` 文件夹。
- 插件不会自动选择、合并、迁移、覆盖或删除任何备份目录；多个目录需要用户手动处理。
- 插件只能检索 DSH 已注册工作区和当前工作区服务；未注册的任意磁盘目录不会被全盘扫描。
- 1.0.4 不再读取旧 `location.json`；该文件可以保留，但不再作为位置依据。

## 升级

1. 下载下方 **Source code (zip)**，按原方式重新添加插件；
2. 打开一次插件页，让 `dsh-backups/restore.ps1` 刷新到 1.0.4；
3. 从 1.0.3 直接升级无需迁移备份；旧备份仍保留在原工作区的 `dsh-backups`；
4. 如果已经存在多个 `dsh-backups`（例如测试工作区残留），先手动移出多余目录，只保留一个，再点「重新检索」。
